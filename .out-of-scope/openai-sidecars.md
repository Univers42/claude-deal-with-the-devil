# Hand-written per-harness sidecar files are out of scope

- Decided: 2026-09-30 · by the maintainer
- Holds while: no harness needs a sidecar the generator does not write

## The concept

Keep one hand-written sidecar file per agent harness in the repo, next to each
agent, describing that harness's display name, short description and invocation
policy, and check them into version control as the source of truth for every
harness at once.

## Why not

The first reversal was a duplicate source of truth: the sidecars had to be
re-verified by hand against a documentation page that moves, and one of them was
never re-read after the field it named stopped being honoured. The second, larger
one is that the set of harnesses is not ours to hold. The evidence is the
capability matrix in `doc/HARNESSES.md`: every cell names a documentation page or a
local run, and the column set changes with whatever a new harness ships.

- the matrix and its evidence: `doc/HARNESSES.md`
- what one of the sidecars had to duplicate by hand: the display name and the
  short description, both of which are already in the agent's own `description:`

## Prior requests

- 2026-09-30 (planning pass): hand-maintain a sidecar per harness so a second harness
  could read the kit without the plugin.
- 2026-09-30 (planning pass, same day): supersede that with generated exports, and
  record the reversal here rather than deleting the idea.

## Reopen when

Two harnesses exist locally at once and at least one of them cannot be reached by
the generator, verified the way `doc/HARNESSES.md` verifies a cell (a local run, a
cited page, a date). Then the sidecar is generated by the same tool as the rest,
never hand-kept.
